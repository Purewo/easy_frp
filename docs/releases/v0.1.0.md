# v0.1.0 Release Notes

First closed backend release for the direct frp port exposure workflow.

## Scope

This version focuses on making local service exposure simple and predictable:

- Run a local backend on `127.0.0.1:7410`.
- Manage one or more frps nodes.
- Create TCP, UDP, and HTTP exposure rules.
- Publish local HTTP services through wildcard HTTPS domains handled by the frps server side.
- Apply changes immediately by rendering and reloading frpc configs.
- Provide the same behavior through API, UI-facing contracts, and CLI commands.

XTCP, visitor/server pairing, and virtual LAN or room-based networking are intentionally not included in this release.

## Included

- Local client API documented in `docs/local-client-api.md`.
- OpenAPI contract for frontend integration in `openapi/local-client.yaml`.
- Multi-node frps management.
- One frpc process/config/log/admin port per active node.
- Port rule CRUD for TCP, UDP, and HTTP.
- HTTP custom domain and subdomain support.
- Host header rewrite for local development servers.
- Node diagnostics through API and CLI.
- CLI commands for node and port rule management.
- GitHub CI for backend tests, backend vet, frontend lint, and frontend build.

## Runtime Notes

Real frps tokens must stay outside git. Use `.env.example` only as a variable template, then provide the real value through the shell or local ignored `.env` files.

The current public HTTPS deployment model expects the frps side to provide:

- wildcard DNS for the base domain,
- wildcard TLS certificate,
- Nginx HTTPS termination,
- Host-preserving proxy to the frps HTTP vhost port.
