# v0.2.0 Release Notes

Stable backend release for XTCP/STCP room mode.

## Scope

This version adds room-based NAT traversal on top of the existing direct port exposure workflow:

- Run a remote room control server and a room-only frps.
- Create host rooms and one-time room codes.
- Join rooms from another client through XTCP or explicit STCP fallback.
- Manage local room rules through the local client backend on `127.0.0.1:7410`.
- Keep the remote room record API separate from local frpc process state.

## Included

- Public room APIs under `/v1/rooms...`.
- Local room APIs under `/v1/client/rooms...`.
- NAT diagnostics under `/v1/client/network/interfaces` and `/v1/client/xtcp/nathole/discover`.
- CLI room commands: `frp-panel client host`, `frp-panel client join`, and `frp-panel client rooms`.
- XTCP and STCP room config rendering for frp 0.68.1.
- Room frps HTTP plugin authorization by room/device metadata.
- Detached frpc process support for Windows SSH and Remote Desktop sessions.
- Local prevalidation before remote room creation or join.
- Best-effort remote room cleanup when host local apply fails.
- Redaction for room codes, device tokens, auth tokens, admin passwords, and secret keys in local logs/errors.
- Frontend contract docs and generated OpenAPI TypeScript types.

## Runtime Notes

The current development default room control server is `http://149.118.158.112:18080`. For private deployments, start a control server with a room-only frps and pass the replacement server URL through `--server` or `serverBaseURL`.

Room codes are secrets. They are returned only by the immediate host-create response and should not be logged, embedded in URLs, or sent to analytics.
